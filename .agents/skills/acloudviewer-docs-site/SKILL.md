# ACloudViewer Docs Site

## Steps

1. **Identify the target and preserve the baseline.** Run `pwd`, `git rev-parse HEAD`, `git status --short --branch`, and `git diff --cached --name-only`. Read the current [Documentation workflow](<.github/workflows/documentation.yml>), [docs Dockerfile](<docker/Dockerfile.docs>) and [`build_docs` helper](<util/ci_utils.sh>); reading the Dockerfile does not imply running Docker. For a remote failure, match the full `head_sha`, save the attempt/job metadata and log, then find the first substantive error in its actual phase/layer ([exact-SHA CI](<references/exact-sha-ci.md>)). For integration onto latest main, use a detached worktree and a path-limited, hashed patch with explicit dependency and reverse-apply checks; do not resolve conflicts in the user's working tree ([isolated integration](<references/integration-maintenance.md#isolated-integration>)).
2. **Verify one docs environment and run only the necessary build stages.** Resolve `DOC_PY` to the absolute docs venv interpreter, record `"$DOC_PY" -V` and `"$DOC_PY" -c 'import sys, playwright; print(sys.executable, playwright.__file__)'`, and put its bin directory first for subprocesses (including scripts invoking `python3`). Use this interpreter for website preparation dependencies, archive/download probes, Doxygen/parallel, Sphinx and browser guards. Check actual exit markers and logs, not tool transport success. For a full native replay run `source util/ci_utils.sh` then `build_docs ON` with `CI=true`, measured `NPROC` and `CMAKE_BUILD_PARALLEL_LEVEL` per [native replay](<references/native-replay.md>). Stage 1 is Release headless with the actual CI notebook set and strict Sphinx; stage 2 is Release GUI/WebRTC/ML with PyTorch ops, full regenerated Python API/examples and versioned Doxygen with strict Sphinx. Record actual import paths and both phase settings before reconfiguration. Keep one owner per tree; if changing concurrency, stop only the owned job and verify children exited before resuming; honor the aggregate cap including unrelated jobs.
3. **Isolate the failing phase without weakening it.** Capture structured notebook cell failures and verify Matplotlib/IPython in the actual kernel; isolate only confirmed stale generated inputs. Use the original notebook for [headless/Poisson checks](<references/native-replay.md#headless-poisson-and-dataset-diagnostics>); a screenshot does not exercise subsequent vertex deletion. Use [Sphinx diagnostics](<references/sphinx.md>) for inline `.. note:: …` plus body and real ML class transport (`Pipe.recv → _ForkingPickler.loads → ModuleNotFoundError: ml3d`): negative worker-only vs valid early parent `CLOUDVIEWER_ML_ROOT`, no-compile `docs-guards`, then full `python -m sphinx -E -a -j4 -W` with a fresh explicit doctree and verified GUI/ML source. Reuse compiled, notebook or Doxygen output only with unchanged inputs. For Doxygen formula PNGs or other missing assets, follow [source repair and revalidation](<references/resource-repairs.md>): actual CI install/first-error logs, unchanged real TeX, version-bound manifests, Pillow validation and a missing-resource negative control. Rebuild HTML for source/static changes; do not patch published HTML to hide a generator defect.
4. **Test maintenance failures and stage authentic inputs.** Run the offline [maintenance matrix](<references/integration-maintenance.md#offline-maintenance-matrix>) with the verified interpreter: valid empty vs API/parse/download failures, valid dev entry, current release deduplication, non-overwriting backup replacement, current schema/UTC and pagination, Doxygen entry and output checks. After strict build success verify the actual Actions run/artifact identity, SHA-256 and entry layout, not a local approximation; derive notebook delivery from archive members and rendered source links. Recover every existing historical version with provenance. Use fresh staging, [website preparation](<docs/automation/scripts/prepare_website.sh>) and [unified deployment](<docs/automation/scripts/deploy_unified_docs.sh>) as in [staging and browser acceptance](<references/staging-and-browser.md>) and [artifact and capacity evidence](<references/integration-maintenance.md#artifacts-and-capacity>). Keep separate real main and release replays where requested. Preserve history, versioned C++ HTML and both capacity gates; remove site-root intermediates on both rsync and cp paths. Packaging-only fixes do not require recompiling C++.
5. **Run fixture guards, then verify the exact merged tree.** Follow the [real-artifact playbook](<references/real-artifact-acceptance.md>) and run the bundled [browser and resource probe](<scripts/verify_merged_site.py>) with full SHA, run ID, `unified-deploy/`, a new output directory and independent version inventory. Use real routes at `/ACloudViewer/`, directory entries, actual SVG links, responsive widths (including 1024/390), both switcher generations, deep routes and custom 404 controls. Scan the entire tree, not only browser samples. Preserve raw failures; classify test errors, proven unused templates and real defects separately. Preserve archive HTML/styles and switcher contracts; fill only missing archive resources from the right source. After repair, rebuild/remerge and rerun browser, resource, preservation and capacity gates; match subsequent CI to the **new** SHA. No real tree means real acceptance has **not run**.
6. **Separate candidate, deployment and live outcomes.** For a local-only or production read-only request, do not commit, push, dispatch, merge, upload or mutate release assets or Pages. Compare the feature and actual remote main/release runs, publishing step and live verifier separately, then verify the established production URL with a real browser using [production read-only acceptance](<references/real-artifact-acceptance.md#production-read-only>). Without an identity chain, report what was observed without claiming an exact deployed SHA. Only with authorization and after the relevant gates pass, use the [focused commit and exact-SHA remote procedure](<references/exact-sha-ci.md>); dispatch once only if needed and authorized. Feature `docs-guards` or an entire green feature run is not production acceptance.

## Pitfalls

- A quiet job is not necessarily stalled. Check compiler CPU/state, RSS, memory/disk, logs and nested generator flags; two separate `-j` settings are not a global bound. Track background IDs, collect terminal statuses and do not duplicate running work.
- `python -I` ignores `PYTHONPATH`; a venv name alone does not prove interpreter, kernel or package identity. An old system Python can break an archive probe at `removeprefix` before it tests anything. GUI import, stale generated CUDA pages, distro Pandoc, a copied upstream notebook or zero notebook executions do not prove parity. Do not use Xvfb, change tutorial data, skip failures, disable ML/parallelism or suppress `-W` to get green.
- Doxygen exit 0 plus existing files does not prove an HTML entry or formula images. A synthetic nested TeX error or local missing `latex` does not diagnose CI. CI archive contents need not include `.ipynb` when tutorials preserve the expected GitHub notebook source links.
- A disk-derived manifest can hide dropped history. Compare independent inputs to final versions and root entries. A directory URL need not end in `index.html`; SVG links can be namespaced. Real HTML may load new JS and still throw due to a legacy API/ID regression. Never normalize real 404s or overflow away to make the harness pass.
- Compressed bytes are not published content bytes. A passing gzip check, green old SHA, fixture pass, or part of a repaired build is not a release receipt.

## Verification

Maintain a row per exact SHA/run and scope (fixture, real candidate/main/release replay, live): patch/base and environment, phase exits and notebook executed/failed/skipped counts, Sphinx/Doxygen entry and formula evidence, artifact ID/name/size/hash/root, version inventory and retained-file hashes, size by stage and remaining margin, browser and resource reports, CI/deploy step states and production identity confidence. Mark unrun stages pending; mark **release blocked** for unresolved integrity failures, exceeded capacity or missing required fresh evidence. Record expected refusal separately from unexpected errors and say explicitly whether production publication was attempted.
