# ACloudViewer Docs Site

## Steps

1. **Identify the target and the last verified stage.** From the current repository run `pwd`, `git rev-parse HEAD`, `git status --short --branch`, and `git diff --cached --name-only`. Read the current [Documentation workflow](<.github/workflows/documentation.yml>), [docs Dockerfile](<docker/Dockerfile.docs>) and [`build_docs` helper](<util/ci_utils.sh>). They define the build and archive contract; reading the Dockerfile for parity does not mean running Docker. For a remote failure, match the run's full `head_sha`, archive the job log, and locate the first substantive error and failing Docker layer before reproducing it. Use [exact-SHA CI and evidence](<references/exact-sha-ci.md>).
2. **Run the native two-stage build with one owner per build tree.** In a dedicated venv, from the repository root, use `source util/ci_utils.sh` then `build_docs ON` with `CI=true` and measured `NPROC`/`CMAKE_BUILD_PARALLEL_LEVEL`. Follow [native replay](<references/native-replay.md>) for prerequisites, command blocks, phase snapshots, and aggregate compiler/Sphinx limits. Stage 1 must be Release headless, execute the current CI notebook set, and pass strict Sphinx; stage 2 must be Release GUI/WebRTC/ML with PyTorch ops, regenerate and render full Python API/examples and versioned C++ pages, and pass Doxygen and strict Sphinx. Record the actual package path and phase settings before the same build tree is reconfigured. When changing the cap, stop only the owned job, verify its children exited, and resume with the same inputs/tree; never overlap builds or touch an unrelated one.
3. **Isolate the failing phase without weakening it.** Use structured notebook cell outputs if the console mangles tracebacks. Verify Matplotlib/IPython compatibility in the same kernel environment; back up and isolate only confirmed stale generated API/example trees. For `surface_reconstruction`, a screenshot does not exercise the subsequent vertex deletion: use the original notebook and the [headless/Poisson checks](<references/native-replay.md#headless-poisson-and-dataset-diagnostics>). For GUI-only RST warnings, match the autodoc event order and exercise inline `.. note:: …` plus the body in [Sphinx diagnostics](<references/sphinx.md>). For `Pipe.recv → _ForkingPickler.loads → ModuleNotFoundError: ml3d`, use a real ML **class reference** in a worker-only negative control and a valid parent-path positive control; bootstrap `CLOUDVIEWER_ML_ROOT` before extensions load and wire the no-compile regression into `docs-guards`. After the fix, run full `python -m sphinx -E -a -j4 -W` with a fresh explicit doctree directory and the full GUI/ML source. Reuse notebook output, GUI package and Doxygen only if their inputs are unchanged; retain the scope of each pass in the report.
4. **Replay packaging with actual artifacts.** After successful strict Sphinx and a final HTML entry check, use an independent staging directory, package new HTML, restore real archives, and run [website preparation](<docs/automation/scripts/prepare_website.sh>) and [unified deployment](<docs/automation/scripts/deploy_unified_docs.sh>) as in [staging and browser acceptance](<references/staging-and-browser.md>). On a size failure, measure the staging directories and archive before changing anything. Exclude site-root `doxygen` intermediates and `doctrees` on both rsync and cp paths; keep historical releases, versioned `cpp_api/api/` HTML and the 1 GiB gate. Packaging-only fixes do not require recompiling C++.
5. **Verify the merged real site in a browser at `/ACloudViewer/`.** Run the fixture guards, then run an independent real-artifact check: root, documentation redirect, actual manifest, entry points, common tutorial/Python API deep routes, dev↔archive switching with modern and legacy controls, legacy 404 query/fragment preservation, already-versioned misses without loops, and no local CSS/JS/image failures or JS exceptions. Preserve archived HTML and existing styles; add only a missing shared CSS file, preserve the old switcher API/DOM contract, and resolve nested 404 logo URLs from the site prefix before assigning `src`. Rebuild HTML after Sphinx/static source changes and reassemble in clean staging. If final HTML is not ready, say real-site validation has **not run**, even if fixtures pass.
6. **Only with authorization, commit, push and verify one remote run.** Run the affected guards and review the precise paths. Follow [exact-SHA CI and evidence](<references/exact-sha-ci.md>) for a path-limited commit that preserves staged icons, remote ref verification, one Documentation dispatch, `head_sha` matching and read-only monitoring. Report full SHA, run ID and URL; separate remote guards, complete build and Pages. On a feature branch the cited workflow skips formal Pages deployment; confirm that condition in the current workflow. For local-only tasks, do not commit, push, dispatch or publish.

## Pitfalls

- **Quiet is not stalled:** inspect active compiler CPU/state, RSS, free memory, logs, and generator-specific nested commands. Two `-j` settings are not a global limit. Track background job IDs, collect terminal exit codes, and do not launch duplicates.
- **Wrong inputs can yield convincing output:** `python -I` ignores `PYTHONPATH`; venv Python alone does not prove which package/kernel ran. A GUI import, stale CUDA page, distro Pandoc, a copied upstream notebook, or a zero-notebook summary is not CI parity. Do not introduce Xvfb, change tutorial data, skip failing pages, disable ML/parallelism or suppress `-W` to get green.
- **A partial result is not the next gate:** importing GUI or ML, a cheap regression pass, existing Doxygen files, a fixture site or a dispatch receipt cannot stand in for strict full Sphinx, real deployment or a completed exact-SHA run, respectively. An archive command returning nonzero also does not prove files are absent: independently check the expected artifacts and their identity.
- **A manifest can hide loss:** it comes from directories on disk. Compare it with expected versions from validated input archives; do not use it as the only inventory. Do not overwrite historical HTML/CSS or guess historical page paths. A legacy page may load new JS yet throw because the old API or IDs disappeared.

## Verification

Record a per-stage ledger: source SHA plus local patch state; Ubuntu/tool and dependency versions; venv, kernel and imported package paths; actual parallel bounds and build settings; stage exit codes; per-notebook executed/failed/skipped counts and structured failures; strict Sphinx/API and Doxygen evidence; staging inputs/checksums, merged gzip bytes vs `1073741824`, retained versions/C++ pages, guard counts and real-browser report with local resource and JS error counts. For historical comparison, note any unchanged artifact reused and what verified it. If remote verification was requested, also record previous failed-run evidence, new exact-SHA remote run ID/URL, and each job's current conclusion or pending/running/skipped state. Mark unfinished stages incomplete; neither a passing `docs-guards` nor a green feature-branch build certifies Pages.
