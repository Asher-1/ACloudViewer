# Fix missing resources at their source, then revalidate

## Doxygen formulas: pin the evidence, not the diagnosis

1. Match SHA/run/attempt/job first. From the actual CI job log give line numbers/context showing dependency installation (also inspect [CI helper](<../../../util/ci_utils.sh>) and [Docker recipe](<../../../docker/Dockerfile.docs>) in the candidate checkout) and the first substantive LaTeX error, using retained `_formulas.log` if it contains the decisive error. Record actual OS, Doxygen, LaTeX and Ghostscript versions and the **rendered** Doxyfile, not just the template. In the observed Ubuntu 22.04 CI the versions included Doxygen 1.9.1 and Ghostscript 9.55, TeX and Ghostscript were already installed, and missing `amsmath` was the actual failure. Local 1.8.x/missing-command experiments are diagnosis of that environment only; confirm current CI, not a hardcoded assumption.
2. In the detached tree use CI-equivalent tools and two clean output dirs. Use the preserved real dev and historical `_formulas.tex` unchanged; hash each original with `sha256sum`. Capture actual compile commands, exit codes and full logs; **TODO per checkout:** extract the exact Doxygen/LaTeX invocation and image conversion/environment from the job or its retained output, not a guessed command. Compare generated outputs to actual rendered HTML references per version, recording original TeX SHA, formula number/text mapping, PNG path/hash/size/decode and browser receipt. A nested math environment introduced by a hand-wrapped fixture is not evidence against original formulas. Revert only your exploratory edits and use `git diff --exit-code HEAD -- docker/Dockerfile.docs libs/cloudViewer/t/geometry/TriangleMesh.h libs/cloudViewer/t/geometry/PointCloud.h` when these were the trial paths and were clean at baseline; otherwise compare to the saved pre-trial diff. Do not discard others' work.
3. If the verified cause is `amsmath`, set the corresponding `EXTRA_PACKAGES` in [Doxyfile template](<../../../docs/Doxyfile.in>), check it reaches the actual TeX, and keep equations unchanged. Supply a tool only where the verified environment lacks it; do not duplicate CI's install. In [builder](<../../../docs/make_docs.py>), fail if Doxygen fails, lacks its HTML entry, or any referenced local formula PNG is missing, out of bounds or bad. Use Pillow (`Image.open`, require PNG and positive size, `verify`, reopen and `load`), no custom PNG parser; declare Pillow in independent guard CI. Require actual references for the known real formula corpus rather than accepting an empty check. Run `"$DOC_PY" docs/automation/scripts/test_docs_parallelism.py`, capture exact status and output. Positive: real dev and stable generated and decoded (historically 40 and 29, not fixed future counts); negative: in copies remove a required PNG and replace one with an invalid PNG, assert the owner fails even if Doxygen returns 0 and leaves an index. Don't treat unrelated warning noise as evidence of a formula failure.

## Historical source binding and raw plugin image publication

- **Historical formulas:** validate the archive and original TeX bytes against the version-specific source manifest, bind original SHA-256 plus formula numbering/text to verified per-image digests. For each actual HTML reference validate version, local path containment, mapping and decoded PNG; if target absent, add only that PNG under the corresponding historical version at the original URL. Unknown number, TeX/hash mismatch, broken allowed image, or unavailable validated source fails closed; no dev substitution or history overwrite. Use clean staging copies; validate a temp file before placement. Test absent target → fill, existing valid target → untouched, and unknown number, mismatched TeX, unavailable/corrupt source → fail. Capture pre/post digests for HTML, existing PNGs and archive, with zero historical resource repair deletions/rewrites. For each repaired page record page and actual image URLs, HTTP status and browser decode (use explicit routes/images in the [real-artifact playbook](<real-artifact-acceptance.md>)). Report expected capacity refusal and no production publish independently of repaired-image success.
- **Historical C++ main page:** for a real referenced missing image first check same-version `_images`/`images` (validate that it is the correct image), then verify the exact stable tag and use `git rev-parse --verify "refs/tags/${version}^{commit}"` and read-only `git show "refs/tags/$version:docs/images/$image"` from the deploy script's repository. Validate tag/image input and file containment; write a temp file, check success, nonempty and decodable, then place only at the missing location. Record tag commit/path/hash. Prefer a narrow fetch of required tags by the workflow, not fetches or branch guesses inside merge. A missing verified source fails; no current HEAD substitution. Assert existing archive files unaffected. Apply the same provenance/licensing discipline to third-party docstrings (e.g. historical TensorBoard images): verify exact upstream source/revision and permission before copying.
- **Raw HTML plugin images:** Sphinx does not automatically collect those references. Publish the actually referenced local assets in the existing [Sphinx build hook](<../../../docs/source/conf.py>) before removing generated sources; contain normalized paths, check the source even if a target already exists and fail on missing required input. Keep failed-build cleanup separate from publication. Run `"$DOC_PY" docs/automation/scripts/test_docstring_pipeline.py` and do a real small strict Sphinx render of the plugin markup: compare source/output byte hashes, then remove source and rerun incrementally with stale output present; require failure. Keep receipts from both.
- **QCustomPlot:** verify bundled/upstream version (observed 1.3.1), image mapping and redistribution scope; source-code licensing is not blanket permission for non-code artwork. Do not deliver uncertain official PNGs. If the user chooses original illustrations, use the matching API, independent data and new layout, no tracing/reuse, label as original examples, keep historical API text/pages and expected URLs, and record reproducible generator/source/license, mapping, image hashes and decode/browser results. Review semantics and include all required images rather than just prototypes.

## Rebuild and close the gate

Run the applicable maintenance, Doxygen, Sphinx and deploy tests on the integrated candidate. Use fresh build/assembly from changed inputs; preserve failure baseline separately. Repeat actual rendered page loads and full-tree resource audit, compare preservation and both capacity metrics. An assembly can be viewable locally yet correctly refuse publication. Report by candidate SHA/run; local uncommitted repair evidence is patch-scoped; obtain and verify a new run and real artifact for the new SHA when authorized. Do not borrow green checks from the old SHA. Missing resources, failed provenance, unresolved permission, excess size or pending required rebuild/replay means **release blocked**.
